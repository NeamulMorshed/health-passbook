6 · Vertical Timeline — Dashboard Core Component SRS §7
SRS §7 Rule: "Completed tasks move to a Faded state; upcoming tasks are Elevated." The timeline is the primary layout of the Home dashboard. Each item has 4 possible states: completed, in-progress, upcoming, overdue. State is driven by comparing item timestamp with device clock — no user interaction required.

7 · Animation Contract — Antigravity 100ms Standard SRS §6.1
SRS §6.1: "Every button press must result in a UI change within 100ms." All interactive state changes use CSS class-toggling on pre-rendered elements. No JavaScript layout recalculation in the tap-response critical path.
Interaction Type Duration Easing CSS Token SRS Compliance
Button press / tap feedback
scale(0.97) on :active		 80ms cubic-bezier(0.4, 0, 0.2, 1) --t-instant ✓ Within 100ms
Timeline item state toggle
Log → Logged class swap, opacity/shadow change		 80ms cubic-bezier(0.4, 0, 0.2, 1) --t-instant ✓ Within 100ms
Input focus border
border-color: border → primary		 80ms cubic-bezier(0.4, 0, 0.2, 1) --t-instant ✓ Within 100ms
Chip / Tab selection
background, color, border-color		 150ms cubic-bezier(0.4, 0, 0.2, 1) --t-quick ✓ Within 100ms visual delta
Progress bar fill
width animation on data update		 250ms cubic-bezier(0.4, 0, 0.2, 1) --t-standard Decorative — post-render
Screen / page transition
translateX + opacity slide		 320ms cubic-bezier(0.2, 0, 0, 1) --t-page SRS §6.1: 60fps required
Bottom sheet open
translateY(100%) → translateY(0)		 320ms cubic-bezier(0.2, 0, 0, 1) --t-page Only transform — GPU composited
Snackbar / Toast appear
translateY + opacity		 250ms cubic-bezier(0.4, 0, 0.2, 1) --t-standard Post-action feedback
GPU Compositing rule: All animations must use only transform and opacity — never width, height, top, left, or margin — to guarantee 60fps on mid-range Android hardware (SRS §6.1). The only exception is progress bar width, which runs post-render and is not in the interaction critical path.

10 · Design Decision Summary
Decision Choice Reason
Primary color #5C6FFF Matches reference image's blue-indigo gradient hero & active nav; conveys trust in a medical context
FAB color #3DBE7A — Success Reference image uses green FAB; green = "action / positive" in health contexts; contrasts with primary
Font Inter (Google Fonts) Reference image's clean numeric display and minimal UI language; excellent at all weights 300–900
App background #F0F2F8 (blue-gray tint) Reference image uses off-white/light gray background; blue tint unifies with primary palette
Icon style 2px stroke, round caps, rounded-square container Matches reference image icon containers exactly; consistent with Lucide/Heroicons library
Dashboard layout Vertical Timeline (SRS §7) SRS mandates timeline; reference shows schedule/timeline in 3rd screen; naturally maps to time-based health tasks
Completed item style opacity: 0.45, shadow: none SRS §7 "Faded state"; sufficient contrast for glanceability; items remain readable, not invisible
Upcoming item style Elevated shadow + translateX(2px) SRS §7 "Elevated"; subtle lift draws eye to actionable items without aggressive color changes
100ms tap response 80ms CSS transform/opacity only SRS §6.1; transform+opacity are GPU-composited — no layout recalculation on any Android device
Splash illustrations CSS-animated SVG (Lottie-compatible) No external file dependency; animations embedded inline for instant load; slot-replaceable with .lottie files
Duplicate warning Bottom sheet (not alert dialog) SRS §5.2; bottom sheets are non-blocking, dismissible with swipe, match reference image's interaction pattern
Offline sync feedback Error-colored snackbar, 4s SRS §5.1; snackbar is ephemeral, non-blocking, references sync queue status without modal interruption
